# Code review — 2026-11-24

Review of `feat/live-dashboard` at `8e8c559` (live dashboard and ESP32 setup), then the fixes on this branch.

Scope: `src/csi/` (types, synthetic generator, phase sanitization, ESP32 loader, live processor), `tools/live_dashboard/` (server and page), `scripts/record_esp32.py`, `scripts/flash_esp32_boards.ps1`, `firmware/esp32/configure_esp_csi.py`, tests, CI, and the docs that describe those pieces.

Method: read the code, ran the suite (34 tests, all passing, before any edit), and reproduced the signal-processing and parser failures below under NumPy 2.5 / SciPy 1.16. This machine has no ESP32, so nothing here re-measures the hardware numbers already in the docs.

Severity is about the effect on this repo: a wrong phase into a future model, a crashed capture, or a local page running attacker-controlled markup. It is not a CVSS score.

## Findings

| ID | Severity | Where | Finding | Status |
|---|---|---|---|---|
| R1 | High | `src/csi/sanitize.py` | Median filter ran *before* the linear detrend, and SciPy's `medfilt` zero-pads. A recording shorter than the kernel was wiped to 0 (a length-1 nonlinear phase came back as all zeros; mean absolute error against the true residual was 0.41 rad). With a fresh CFO/STO offset on every packet, the median stitches subcarriers from different packets and the leftover is not a line (mean absolute error 0.24 rad on a 9-packet synthetic case). | **Fixed.** Unwrap, subtract the least-squares line, then `median_filter(..., mode="nearest")`. The filter is skipped when the recording is shorter than the kernel. Tests cover both failures. |
| R2 | Medium | `src/csi/sanitize.py` | The line was fit against `0 .. S-1`. After DC and subcarrier 1 are dropped, those columns are not one bin apart, so a pure delay is not fully removed. | **Fixed.** Optional `indices`. The live phase trace passes `K_USED`. |
| R3 | High | `src/csi/loaders/esp32.py` | CSI tokens were cast with `dtype=int16`. A value outside int16 raises `OverflowError` on NumPy 2 (that is not a `ValueError`, so the parser did not catch it) and aborts the file or the live loop. NumPy 1.x wraps the same token into a plausible sample. | **Fixed.** Tokens outside int16, non-integers, and lists longer than 8192 drop the line. |
| R4 | Medium | `src/csi/loaders/esp32.py` | One non-numeric `local_timestamp` raised `ValueError` and discarded the whole log. | **Fixed.** Any bad timestamp falls back to the packet index for that file. `metadata["timestamps_from"]` says which. |
| R5 | Low | `src/csi/loaders/esp32.py` | One RSSI field that failed an `isdigit` check dropped the RSSI of every packet (`None`). | **Fixed.** One NaN per bad packet, same length as the recording. |
| R6 | Medium | `src/csi/loaders/esp32.py` | With no header row, every line was read with the ESP32-CSI-Tool column names. An esp-csi line has 24 fields, not 25, so `first_word=1` was ignored and the junk first word was kept. | **Fixed.** 24 fields and no header selects the esp-csi layout. A header, when present, still wins. |
| R7 | Medium | `tools/live_dashboard/index.html` | Pills were built with `innerHTML`. The sender MAC and the serial-port error string come from outside the page. A corrupt or hostile CSI line could run script in the browser that has the dashboard open. | **Fixed.** Pills, the log, and the recordings table use `textContent`. |
| R8 | Low | `tools/live_dashboard/server.py` | `Content-Length` was trusted. A negative length makes `rfile.read(-1)` block until the client hangs up. There was no upper bound. | **Fixed.** Length must be 0..16384 bytes, and the body must be a JSON object. |
| R9 | Low | `tools/live_dashboard/server.py` | `POST /api/calibrate` and `POST /api/record/stop` accept an empty object. A page on another origin can submit that with a form POST (no CORS preflight). | **Fixed.** An `Origin` other than loopback (`127.0.0.1`, `localhost`, `::1`) is rejected with 403. Clients that send no `Origin` (curl, the dashboard's own `fetch`) still work. The socket stays on `127.0.0.1`. |
| R10 | Low | `src/csi/live.py` | Non-finite floats were passed to `json.dumps`, which emits `NaN` / `Infinity`. `JSON.parse` rejects those and the event stream dies. | **Fixed.** Non-finite numbers become `null`. |
| R11 | Low | `src/csi/live.py` | `POST /api/threshold` accepted NaN and negative values, which makes the presence comparison meaningless. | **Fixed.** Finite, from 0 to 10. Calibration seconds from the HTTP API must be 1..120. |
| R12 | Low | `src/csi/types.py` | `synthetic=True` required `source="synthetic"`, but `source="synthetic"` with `synthetic=False` was accepted. That breaks the "synthetic data is always labelled" rule in one direction. | **Fixed.** The flag and the source have to agree. |
| R13 | Low | `scripts/record_esp32.py` | The printed packet rate used the *requested* duration. Stopping with Ctrl+C under-reported packets/s. The sidecar did not record how long the capture actually ran. | **Fixed.** Rate and `seconds_recorded` use the monotonic time the port was open. The file is opened with `O_EXCL` so a race cannot truncate an existing capture. |
| R14 | Low | `docs/hardware/esp32.md` | The comparison table said the ESP32 packet rate is "~100+". The measured paragraphs in the same doc say ~70 at the 40 MHz default and ~90 after the L-LTF-only setup. | **Fixed.** The table now matches the measured paragraphs. |
| R15 | Low | `.github/` | There was no workflow. "CI green" was not a check anyone could fail. | **Fixed.** `.github/workflows/ci.yml` runs pytest on Python 3.12. Torch is not installed there; nothing in `src/` or `tests/` imports it. |
| R16 | Low | `scripts/flash_esp32_boards.ps1` | `idf.py build` was piped into `Select-Object` before `$LASTEXITCODE` was checked. On some PowerShell hosts that hides a failed native command. | **Fixed.** The exit code is checked on the `idf.py` process itself. The build log is no longer trimmed. |
| R17 | Low | `index.html` | The waterfall drew a "0" tick on the first positive subcarrier, because DC is not in `K_USED`. | **Fixed.** Ticks are drawn only for indices that are actually present. |
| R18 | Low | `index.html` | The threshold slider stopped at 0.4. A calibration of `mean + 4·std` can land above that, and the control then could not show it. | **Fixed.** The slider starts at 1 and grows if the live threshold is higher. |
| R19 | Low | `src/csi/live.py` | Presence was recomputed from a single score against the threshold. On the demo feed the score sits on the line and the event log filled with "above" / "under" several times a second. | **Fixed.** Presence latches on at the threshold and releases at 85% of it. The activity timeline uses the same latch. |

## Checked, no defect found

- The HTTP server binds `127.0.0.1` only. There is no flag to widen that. Covered by `tests/test_server.py`.
- Recording refuses to start without consent and without a known label, in both the script and the dashboard.
- `generate_room_csi` sets `synthetic=True` and `source="synthetic"`. The demo banner says the packets are simulated.
- ESP32 pairs are imaginary-then-real, L-LTF is reordered from `0..31, -32..-1` to `-32..31`, and a 384-value HT40 record keeps the first 128 values. Existing tests construct the bytes and check the complex values.
- Microsecond timestamps unwrap across `2**32`. That test still passes.
- `firmware/esp32/configure_esp_csi.py` refuses to write if a pattern is missing, and it does not report a change when the file is already in the desired state. It rewrites every matching assignment in `app_main.c` (both chip branches, if both are present). That is what we want for this project's settings. Not re-run against a newer esp-csi than the one the hardware notes describe.
- The motion-score formula (gain-normalised coefficient of variation) was left as it was. The docstring records a still-room measurement of about 0.026 on the real boards. Changing the formula would silently invalidate that calibration. The new spectrum, breathing, occupancy and static-shape figures sit beside it and are labelled as estimates.

## Not claimed, and not "fixed" into a claim

- No accuracy number for presence, occupancy, breathing, or pose was measured on a labelled recording. The dashboard says so on the panels.
- One ESP32 link (1×1, ~52 L-LTF subcarriers) is not the 3×3, 30-subcarrier capture in the DensePose-from-WiFi paper. The body figure is an animation until a model with `trained = True` is passed to `--pose-model`.
- Phase sanitization still cannot invent absolute phase. The per-packet slope and mean are removed. What remains is only useful relative to itself.
- A timestamp fallback replaces the whole clock with the packet index when any one timestamp is bad. That is safer than crashing; it is not a repaired clock.
- This review did not flash boards or sit in the room. The hardware figures in `docs/hardware/esp32.md` are the ones from the November 2026 bring-up, not new measurements.
